# 유리나무 작업 허브 (YURIWOOD WORK HUB)

작업에 쓰는 웹사이트를 **1차 카테고리 → 2차 카테고리 → 사이트 카드** 구조로 정리하고, 목적별 **작업 런처**와 통합 검색으로 바로 찾아 여는 개인 작업 링크 허브입니다.
HTML · CSS · 순수 JavaScript로만 만든 정적 페이지이며, 프레임워크·빌드 도구·서버·로그인 기능은 사용하지 않습니다.

공개 페이지: <https://yuriwood50-ai.github.io/yuriwood-work-hub/>
디자인 시스템: **Modern Editorial Blue** (기준 문서 [`DESIGN.md`](DESIGN.md))

## 화면 구성

- **왼쪽 사이드바**: 상위 메뉴(대시보드 + 6개 1차 카테고리)를 누르면 하위 메뉴가 아코디언으로 열립니다. 한 번에 하나의 상위 메뉴만 펼쳐집니다. 메뉴마다 사이트 개수가 함께 표시됩니다.
- **대시보드 하위 메뉴**: `전체 사이트`(1차 카테고리별 전체), `자주 쓰는 사이트`(`quick: true`), `내 프로젝트`(`project: true`).
- **1차 카테고리 상위 메뉴**: 그 안의 2차 카테고리를 블록으로 나눠 한 화면에 보여 줍니다.
- **2차 카테고리 하위 메뉴**: 해당 2차 카테고리의 사이트만 보여 줍니다.
- **상단바**: 햄버거 버튼(모바일) · 통합 검색창 · 오늘 날짜. 검색창은 스크롤해도 화면 위에 고정됩니다.
- **본문**: 브레드크럼 → 현재 화면 이름 → 사이트 개수 → (전체 사이트 화면에서만) 작업 런처 → 사이트 카드 그리드 순서로 표시됩니다.
- **사이트 카드**: 카테고리 경로, 사이트 이름, 한 줄 설명, 검색 태그, 바로가기 표시가 들어갑니다. 모든 외부 링크는 새 탭(`target="_blank"`, `rel="noopener noreferrer"`)에서 열립니다.
- **모바일**: 사이드바가 드로어로 바뀌고, 바깥 영역 클릭 또는 `ESC` 키로 닫힙니다. 검색창·메뉴·카드가 모두 한 열로 정렬됩니다.

## 작업 런처

`전체 사이트` 화면에서 **검색창 아래, 사이트 목록 위**에 표시되는 목적별 시작점입니다.
목적을 고르면 그 아래 상세 패널 하나에 **작업 단계**와 **필요한 도구**가 펼쳐집니다.

| 번호 | 런처 | 단계 | 도구 |
| --- | --- | --- | --- |
| 01 | 수업 준비 | 5 | 11 |
| 02 | AI 스톡 제작 | 6 | 7 |
| 03 | SNS · 웹툰 발행 | 5 | 9 |
| 04 | 앱 · 웹 업데이트 | 6 | 12 |
| 05 | 전자책 · 상품 관리 | 5 | 9 |
| 06 | 포트폴리오 관리 | 4 | 9 |
| 07 | 지원사업 신청 | 5 | 10 |

동작 규칙

- 런처는 **`전체 사이트` 화면이고 검색 중이 아닐 때만** 보입니다. 자주 쓰는 사이트·내 프로젝트·1차·2차 카테고리·검색 결과 화면에서는 숨겨집니다.
- 카드를 누르면 상세 패널이 열리고, 다른 카드를 누르면 **패널 내용이 교체**됩니다. 패널은 항상 하나뿐입니다.
- 사이트를 **한꺼번에 열지 않습니다.** 도구는 각각 새 탭 링크로만 제공합니다.
- 닫기 버튼, 다른 메뉴로 이동, 검색 시작 중 어느 것으로든 패널이 닫힙니다.
- `Escape` 우선순위: 모바일 드로어 닫기 → 검색 초기화 → 런처 닫기.
- 카드는 실제 `button` 요소이며 `aria-expanded`와 `aria-controls`로 패널과 연결됩니다.

### 사이트 개수 표시에 대해

한 사이트를 여러 카테고리에 배치할 수 있으므로, `전체 사이트` 화면에서는 카드가 65장보다 많이 보입니다.
이 경우 상단에 `사이트 65개 · 카드 91장 (여러 카테고리에 함께 배치된 사이트 포함)`처럼 **고유 사이트 수와 카드 수를 함께** 표시합니다.

## 통합 검색

상단 검색창 하나로 다음을 모두 검색합니다.

- 사이트 이름
- 사이트 한 줄 설명
- 1차 카테고리 이름
- 2차 카테고리 이름
- 검색 태그(`tags`)

동작 규칙

- 입력하는 즉시 결과가 갱신됩니다.
- 검색어 앞뒤 공백은 제거하고, 영문 대소문자는 구분하지 않습니다.
- 공백으로 낱말을 나눠 입력하면 **모든 낱말을 포함한** 사이트만 나옵니다. (예: `이모티콘 카카오`)
- 결과 개수를 `검색 결과 N개`로 표시합니다.
- 결과가 없으면 `검색 결과가 없습니다` 안내와 검색어 변경 안내, `검색 초기화` 버튼을 보여 줍니다.
- `Escape` 키, 검색창의 `×` 버튼, 왼쪽 메뉴 선택 중 어느 것으로든 검색이 초기화됩니다.

## 로컬 실행 방법

빌드 과정이 없으므로 `index.html`을 더블클릭해 브라우저에서 바로 열어도 모든 기능이 동작합니다.

로컬 서버로 확인하려면 이 폴더에서 아래 중 하나를 실행한 뒤 `http://localhost:8000` 에 접속합니다.

```bash
# Python이 설치된 경우
python -m http.server 8000

# Node.js가 설치된 경우
npx --yes serve . -l 8000
```

## 데이터 수정 방법

모든 데이터는 `script.js` 위쪽의 **`CATEGORIES` · `SITES` · `WORKFLOWS` 세 곳에서만** 관리합니다. HTML은 수정할 필요가 없습니다.

### 1. 카테고리 정의 (`CATEGORIES`)

```js
{
  id: "dev",                 // 1차 카테고리 식별자 (중복 금지)
  title: "개발 · 배포",       // 사이드바 상위 메뉴 이름
  subs: [
    { id: "deploy", title: "저장소 · 배포" }, // 2차 카테고리 (id는 같은 1차 안에서 중복 금지)
  ],
}
```

### 2. 사이트 정의 (`SITES`)

```js
{
  id: "github",                                  // 내부 식별자 (중복 금지)
  name: "GitHub",                                // 카드 제목
  url: "https://github.com/",                    // 새 탭으로 열리는 주소
  desc: "코드와 문서를 버전으로 관리하고 백업하는 저장소입니다.", // 카드 한 줄 설명
  tags: ["개발", "저장소", "깃허브", "git"],       // 검색용 키워드
  placements: ["dev:deploy"],                    // "1차ID:2차ID" 배열
  quick: true,                                   // (선택) 자주 쓰는 사이트에 표시
  project: true,                                 // (선택) 내 프로젝트에 표시
}
```

### 3. 작업 런처 정의 (`WORKFLOWS`)

```js
{
  id: "class-prep",          // 런처 식별자 (중복 금지)
  number: "01",              // 카드 왼쪽 위 번호
  title: "수업 준비",
  desc: "수업 기획부터 자료 제작과 일정 관리까지",
  steps: ["수업 주제와 목표 정하기", "수업안 작성하기"],  // 순서 있는 작업 단계
  siteIds: ["chatgpt", "google-docs", "canva"],        // SITES의 id만 적는다
}
```

**`siteIds`는 기존 `SITES`의 `id`를 참조하기만 합니다.**
사이트 이름·주소·설명을 `WORKFLOWS`에 다시 적지 않습니다. 화면에 보이는 도구 이름과 설명은 실행 시점에 `SITES`에서 그대로 가져옵니다.

```js
const site = SITES.find((item) => item.id === siteId);
```

없는 id를 적으면 조용히 넘어가지 않고 브라우저 콘솔에 오류로 보고합니다.

```
[작업 런처] "class-prep"가 SITES에 없는 사이트 id를 참조합니다: "없는-id"
```

런처를 추가하려면 `WORKFLOWS`에 객체를 하나 더 넣고 `number`를 이어서 붙이면 됩니다. 카드·패널·개수는 자동으로 생성됩니다.

### 4. 한 사이트를 여러 카테고리에 넣기

**객체를 복제하지 않습니다.** `placements` 배열에 배치를 추가하면 됩니다.

```js
// Replit 하나를 '코딩 · 실습'과 '앱 · 웹 제작' 두 곳에 표시
placements: ["dev:practice", "dev:build"],
```

이렇게 하면 이름·설명·URL을 한 곳에서만 고쳐도 모든 화면에 함께 반영됩니다.

### 5. 자동으로 계산되는 것

- 사이드바 상위·하위 메뉴와 각 메뉴의 사이트 개수
- 본문 블록 제목과 `NN SITES` 표시
- 상단 브레드크럼과 현재 화면의 사이트 개수
- 푸터 총계(`65 SITES · 6 CATEGORIES · 23 GROUPS`)
- 검색 대상 문자열(이름 · 설명 · 태그 · 1차/2차 카테고리 이름)
- 런처 카드의 단계·도구 개수와 상세 패널 내용

첫 화면은 `script.js`의 `DEFAULT_VIEW`(기본값 `"all"` = 전체 사이트)로 지정합니다.

## 배포

빌드 과정이 없으므로 폴더를 그대로 올리면 됩니다.

- **GitHub Pages**: `main` 브랜치에 푸시 후 Settings → Pages에서 브랜치와 루트(`/`) 지정 (현재 방식)
- **Netlify**: 사이트 생성 화면에 폴더를 드래그 앤 드롭 (빌드 명령 없음, 배포 디렉터리 `.`)
- **Vercel**: 저장소 연결 후 프레임워크 프리셋을 `Other`(정적)로 지정
